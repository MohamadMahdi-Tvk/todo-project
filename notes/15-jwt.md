# JWT (Json Web Token)

یکی از روش های بسیار متداول و کاربردی در زمینه پیاده سازی احراز هویت است؛ اگر وب سایتی داشته باشیم که کاربران زیادی
داشته باشد و به روش توکن احراز هویت رو پیاده سازی کرده باشیم، فرضا در یک لحظه چند هزار نفر وارد سایت میشوند و این باعث
میشود برای هر کاربر یک بار به دیتابیس درخواست ارسال شود و اون توکن اعتبار سنجی شود و بعد ادامه ی کار انجام شود، اگر هزار
نفر بیان، هزار تا کانکشن باید به دیتابیس برقرار شود و همین موضوع باعث میشود سرعت سایت ما به شدت کاهش پیدا کند، این یکی
از معایب استفاده از توکن اتنتیکیشن است، البته سایت های بزرگی هم هستند که دارن از این روش استفاده میکنند و میشود با
آپگرید کردن منابع سخت افزاری خود تا حدود زیادی این مشکلات را برطرف کنیم. اما روش جی دبلیو تی برای حل این مشکلات مطرح شد.
در ساختار جی دبلیو تی همان اتفاقی میفتد که در توکن میفتد، تنها تفاوتشان این هست که توکنی که جنریت میشود دیگر داخل
دیتابیس ذخیره نمیشود و صرفا یک متن انکریپت شده هست که در درخواست ها ارسال میکنیم، سپس خود اپلیکیشن دیکریپت میکند و
اطلاعات کاربر داخل همان رشته اینکریپت شده وجود دارد، و دیگر لازم نیست برای یکسری از درخواست ها حتما از جدول یوزر، کاربر
واکشی شود. علاوه بر خود توکن (اکسز توکن)، یک مفهومی هم در این ساختار وجود دارد به اسم رفرش توکن که باید پیاده سازی شوند.
برای آغاز کار باید پکیجی به نام سیمپل جی دبلیوتی را روی پروژه دی آر اف خود نصب کنیم:

داکیومنت آن:

`https://django-rest-framework-simplejwt.readthedocs.io/en/latest/`

1. `pip install djangorestframework-simplejwt`

2. به تنظیمات رفته و کانفیگ آن را انجام میدهیم:

```
REST_FRAMEWORK = {
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',
    'PAGE_SIZE': 2,
    'DEFAULT_AUTHENTICATION_CLASSES': [
        'rest_framework_simplejwt.authentication.JWTAuthentication',
    ],
    'DEFAULT_PERMISSION_CLASSES': [
        'rest_framework.permissions.IsAuthenticated'
    ]
}
```

3. به اینسالد اپس هم باید اضافه شود:

`'rest_framework_simplejwt'`

4. به یوآرالز رفته و آدرس های زیر را اضافه میکنیم:

```
from rest_framework_simplejwt.views import (
    TokenObtainPairView,
    TokenRefreshView,
)

path('api/token/', TokenObtainPairView.as_view(), name='token_obtain_pair'),
path('api/token/refresh/', TokenRefreshView.as_view(), name='token_refresh')

```

5. به پست من و آدرس زیر رفته متد را روی پست قرار داده:

`http://127.0.0.1:8000/api/token/`

6. در قالب جیسان یوزر نیم و پسورد را در بادی قرار میدهیم یعنی:

```

    "username": "admin",
    "password": "1234"

```

## Refresh Token:

رفرش توکن اشاره میکند به منقضی شدن توکن، برای بحث امنیت بیشتر، ما یک مفهومی داریم به اسم رفرش توکن که زمانی که توکن اصلی
ما اکسپایر شد، بجای اینکه ما مجددا بیایم و یوزرنیم و پسورد را وارد کنیم که برامون توکن جدید جنریت شود، یک رفرش توکن
داریم که حتی آن رفرش توکن هم تاریخ انتقضا دارد؛ پس ما این رفرش توکن را به یک آدرس خاص ارسال میکنیم، توکن قبلی ما را
آپدیت میکند، یعنی یک توکن جدید میدهد و دیگر لازم نیست بریم یوزرنیم و پسورد بدهیم، آن رفرش توکن باعث میشود توکن اصلی ما
آپدیت شود و آن توکن اصلی ما به اندازه ی مدت زمانی که در تنظیمات درنظر گرفته شده، تاریخ انقضای آن تمدید میشود.

`"ACCESS_TOKEN_LIFETIME": timedelta(minutes=5)`:
یعنی 5 دقیقه توکن اصلی ما قابل استفاده است و بعد از آن منقضی میشود.

`"REFRESH_TOKEN_LIFETIME": timedelta(days=1)`:
باعث میشود توکن اصلی ما 5 دقیقه تمدید شود و بتوانیم دوباره ازش استفاده کنیم؛ مدت زمان این رفرش توکن یک روز هست؛ معمولا
اگر اکسز توکن رو روی 1 روز درنظر بگیریم، رفرش توکن رو مثلا باید روی یک ماه ست کنیم؛ که در بحث رفرش کردن، بدون اینکه لازم
باشد مدام یوزرنیم و پسورد وارد کنیم، توکن مجددا آپدیت شود، که اگر یک ماه به سایت سر نزدیم دیگه کلا باید از اول لاگین
انجام شود؛ پس این تظیمات را در ستینگ قرار میدهیم:

```
from datetime import timedelta

SIMPLE_JWT = {
   "ACCESS_TOKEN_LIFETIME": timedelta(minutes=5),
   "REFRESH_TOKEN_LIFETIME": timedelta(days=1)
}
```

برای تست به پست من و به آدرس زیر و مثل قبل یوزرنیم و پسورد را در بادی قرار داده تا یک توکن و رفرش توکن به ما تحویل دهد:

`http://127.0.0.1:8000/api/token/`

بعد از سند، اکسز توکن را کپی کرده و مثل قبل در قسمت هدرز و با کلید آتورایزیشن، مقدار توکن را در آنجا پیست میکنیم تا
اطلاعات را به ما نمایش دهد. این به درستی کار میکند و مشکلی هم ندارد، اما بعد از 50 ثانیه، یعنی اون زمانی که خودمان برای
اکسز ست کردیم، دیگر با این توکن نمیشود اطلاعات را مشاهده کرد و این توکن منقضی شده است. برای اینکه بتوانیم استفاده کنیم،
باید از قابلیت رفرش توکن استفاده کنیم، پس باید بریم به آدرس زیر، نوع درخواست پست:

`http://127.0.0.1:8000/api/token/refresh/`

باید بریم به قسمت بادی و در قالب جیسان رفرش توکنی که در آدرس قبل داده بود را برایش ارسال کنیم یعنی:

بعد از اینکه سند را بزنیم یک اکسز توکن جدید دریافت میکنیم که میتونیم آنرا کپی کرده و در قسمت هدر درخواست قرار بدهیم تا
بتوانیم اطلاعات را مشاهده کنیم.

این رفرش توکن هم برای امنیت هست و هم برای یو ایکس؛ در مباحث امنیتی اگر ما بخواهیم 1 دقیقه کاربر رو لاگین نگه داریم و هر
سری برای استفاده کردن از سایت از او یوزرنیم و پسورد بخواهیم، واقعا از نظر یوایکس بد هست و کاربر هیچوقت توی اون سایت
فعالیت نمیکند، برای اینکه بخواهیم یوایکس بهتری هم داشته باشیم یک رفرش توکن درنظر گرفته میشود، این رفرش توکن باعث میشود
توکن کاربر را مجددا بدون اینکه لازم باشه کاربر لاگین کند و دوباره یوزرنیم و پسوردش را ارسال کند، توکن او را آپدیت کنیم.
ما این رو در بک اند پیاده سازی میکنیم و اون کسی که سمت فرانت کار میکند باید این موضوع را بداند و ازش استفاده کند. این
پکیج قابلیت های زیادی دارد که پیشنهاد میشود داکیومنت آن را مطالعه کنید.
